# Audit lane — documentation hub

The per-bank BRSA audit-report lane (`bank_audit_*`) has the deepest
documentation in the repo. This page is the map so you land on the right one
without reading all of it. **The docs themselves stay at `docs/` root** because
source docstrings, skills, migrations and `PROJECT_STATE.md` link to them by
name; this hub indexes rather than relocates.

Start with [`SYSTEM_MAP.md`](../SYSTEM_MAP.md) §2 and §3 for how the lane fits
the wider pipeline, then:

## Active

| Doc | Read it when |
|---|---|
| [`AUDIT_DOCUMENT_PLAN.md`](../AUDIT_DOCUMENT_PLAN.md) | **The single active plan.** Complete-document corpus: source identity, independent verification, structured tables/prose, durable storage, admin acceptance. |
| [`AUDIT_PIPELINE.md`](../AUDIT_PIPELINE.md) | You need the lane end-to-end: two-lane model, statement-type registry, repair playbook. |
| [`AUDIT_EXTRACTION_GUIDE.md`](../AUDIT_EXTRACTION_GUIDE.md) | You are writing or fixing one statement extractor (understand → identities → extract → validate → evidence → repair). |

## Where the code lives

- **Extraction + registry + validators** — `src/audit_reports/`
- **Document corpus subsystem** — `src/audit_reports/document_*.py`
- **CLI entry points** — `scripts/sync_audit_reports.py`,
  `scripts/reextract_statement.py`, `scripts/sync_audit_expected.py`,
  `scripts/build_bank_audit_stages.py`
- **Wide-lane builders** — `scripts/graduations/`
- **Diagnostics** — `scripts/diagnostics/`, `scripts/audit_narrow_vs_wide.py`,
  `scripts/triage_partitions.py`
- **Repo rules that bind here** — `AGENTS.md`: fitz-only, never `--force` a
  whole lane, repair one statement at a time, `null` ≠ `0`.
